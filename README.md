# Meu Pior UX

## 📌 Sobre o projeto

O **Meu Pior UX** é um projeto desenvolvido para demonstrar, de forma prática e proposital, como uma interface pode oferecer uma experiência ruim ao usuário.

A proposta é criar um sistema funcional, mas com diversas decisões ruins de UI (Interface do Usuário) e UX (Experiência do Usuário), fazendo com que o usuário tenha dificuldade para entender o que deve fazer, receba informações confusas e encontre obstáculos durante a navegação.

Mesmo com os problemas criados de propósito, o usuário consegue completar o fluxo e chegar à tela final.

## 🎯 Objetivo

O objetivo do projeto é compreender a importância de uma boa experiência do usuário, identificando problemas de usabilidade e entendendo como essas escolhas poderiam ser corrigidas em uma interface real.

## 🚨 Problemas de UX/UI utilizados

Durante o projeto foram inseridos diversos problemas propositalmente:

* Botões com textos confusos ou contraditórios.
* Elementos visuais exagerados.
* Cores e contrastes inadequados.
* Mensagens de feedback confusas.
* Validações absurdas e pouco claras.
* Contadores e temporizadores que aumentam a pressão sobre o usuário.
* Barra de progresso que pode avançar e voltar.
* Botões que mudam de posição.
* Informações importantes difíceis de encontrar.
* Excesso de elementos na tela.
* Regras de senha exageradas e contraditórias.
* Navegação propositalmente confusa.

## 🔎 Princípios e heurísticas violados

### 1. Consistência e padrões

Os elementos da interface não seguem um padrão visual ou de comportamento consistente.

### 2. Visibilidade do status do sistema

O sistema apresenta mensagens e indicadores que podem confundir o usuário sobre o que realmente está acontecendo.

### 3. Prevenção de erros

Algumas validações foram criadas de maneira exagerada ou inesperada, dificultando o preenchimento correto dos campos.

### 4. Acessibilidade

Foram utilizados contrastes ruins, excesso de cores, animações e elementos que dificultam a leitura e a utilização da interface.

### 5. Clareza

Os textos dos botões e mensagens não deixam claramente indicado qual ação o usuário deve realizar.

### 6. Controle e liberdade do usuário

Algumas ações apresentam comportamentos inesperados, fazendo com que o usuário tenha dificuldade para controlar a navegação.

## 💡 Como seria a versão ideal?

Em uma versão correta da aplicação:

* Os botões teriam textos claros e objetivos.
* As cores apresentariam contraste adequado.
* A interface teria organização visual.
* As mensagens de erro explicariam como corrigir o problema.
* As validações seriam claras e coerentes.
* O usuário teria controle sobre a navegação.
* O progresso seria apresentado de maneira confiável.
* Os elementos seguiriam padrões consistentes.
* A interface seria acessível e fácil de compreender.
* Não seriam utilizados elementos desnecessários para dificultar a experiência.

2. Abra a pasta do projeto.

4. Siga o fluxo apresentado pelo sistema.
5. Complete as etapas até chegar à tela final.

## 🔄 Fluxo do projeto

O fluxo principal da aplicação é:

**Início → Dados → Senha → Segurança → Confirmação → Tela Final**

O objetivo é fazer o usuário passar por uma experiência propositalmente confusa, mas que ainda possa ser concluída.

## 🎓 Conclusão

O projeto demonstra que uma interface não deve ser avaliada apenas pela aparência. Uma aplicação pode funcionar tecnicamente e ainda proporcionar uma experiência ruim para quem a utiliza.

A atividade permitiu compreender melhor a diferença entre **UI** e **UX**, além de mostrar a importância de clareza, acessibilidade, consistência, feedback e facilidade de uso.
